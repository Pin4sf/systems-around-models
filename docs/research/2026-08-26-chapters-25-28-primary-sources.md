### Observed mechanisms

- The runtime centralizes identity, policy, scheduling, persistence, and the agent turn, while a selected harness adapter drives the same core and `execute` reaches a scope-specific sandbox. People and shared rooms receive separate scope-owned resources rather than one undifferentiated global workspace. This is an implementation topology, not proof of isolation. ([README architecture](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/README.md#architecture))
- Resource references distinguish files, skills, deployments, crons, and service credentials. Grant reads are audience-aware; personal owners and current group/channel membership are checked at the scope seam; publication defaults fail toward an owner-only audience when membership or visibility cannot be resolved. ([resource references](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/acl/resource-ref.ts), [ACL store](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/acl/acl-store.ts), [publication audience](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/resolution/publish-audience.ts))
- Security posture is a composable org floor: `strict` requires approval for almost every harness tool call, `auto` screens supported external inputs, and `dangerous` removes those two layers. The separate command policy still applies allow/deny/require-approval rules and cannot be loosened below its org floor. ([posture source](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/security/security-posture.ts), [command policy](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/policy/command-policy.ts))
- The Postgres run store represents queued/running/terminal work with leases, heartbeats, attempt counts, a per-session running constraint, deduplication, and indexed tool-call records. Audit records are durable evidence keyed by principal/action/resource/scope/status; they are not preventive controls. ([run-store implementation](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/runs/postgres-run-store.ts), [audit implementation](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/src/admin/postgres-audit-log.ts))

### Unknowns and falsifiers

QM explicitly calls itself early experimental software, assumes one organization of authenticated internal users, and says it is not a hardened public or multi-tenant boundary. Its security document also says command scanning is bypassable, browser work skips some core gates, credentials are plaintext while used, credential “purpose” is not enforced authorization, screening is incomplete, egress depends on backend enforcement, admins can read sensitive content, and some durable data has no expiry. ([security boundary and known limitations](https://github.com/yc-software/qm/blob/e4f928837bb15af24ed58ce00557a41ed140f394/SECURITY.md))

No deployment, cross-scope non-interference test, worker-crash recovery test, or adapter-parity run was performed here. The chapter's mechanism claims are falsified by an unauthorized cross-scope read/write/delivery in a supported topology, a duplicated non-idempotent effect after lease recovery, loss of a queued run after worker failure, a harness switch that changes identity or grants, or acceptance of an egress policy the chosen backend cannot enforce. Do not call the command policy containment, audit prevention, or resource scopes proof of isolation.

## Chapter 26 · Cloudflare Think and Cloudflare Agents

### Identity and revision boundary

Think and Agents are distinct packages in one official [`cloudflare/agents`](https://github.com/cloudflare/agents) monorepo, not two independent repositories. The `agents` package is the lower-level Durable Object runtime SDK; `@cloudflare/think` is an opinionated agent harness built on it. The released pair—`agents` `0.21.0` and Think `0.16.0`—shares commit [`d424945`](https://github.com/cloudflare/agents/commit/d42494503efe836a073fbf911fae1fbd12253198). Current `main` [`f08ee06`](https://github.com/cloudflare/agents/commit/f08ee06fd610756de0d8abf539dfe9b746bdd7c5) is 17 commits later.

Think `0.16.0` removed the convention-driven framework, generated entrypoints, CLI, and Studio while retaining an explicit runtime for hand-written Worker entries. Do not teach current Think as the earlier batteries-included scaffolding framework. ([Think 0.16 release](https://github.com/cloudflare/agents/releases/tag/%40cloudflare%2Fthink%400.16.0))

### Observed Agents mechanisms

- An Agent is Durable Object-backed: SQLite holds state and the runtime broadcasts changes to connected clients while exposing HTTP/WebSocket routing, RPC methods, schedules, queues, durable fibers, sub-agents, and MCP integrations. ([package exports](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/packages/agents/package.json), [state documentation](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/docs/agents/state.md))
- Sub-agents are lazy, idempotently addressed Durable Object facets recorded by the parent. They have logical state, schedules, and fibers but share the parent's physical alarm and placement; “sub-agent” therefore does not imply an independent physical worker. ([sub-agent boundary](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/docs/agents/sub-agents.md))
- `runFiber` persists work/checkpoints for recovery after eviction, while `startFiber` adds durable acceptance and an idempotency key. Cancellation is cooperative: a callback that ignores it may continue after the ledger reports aborted. Durable resumption does not make arbitrary external effects idempotent. ([durable execution](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/docs/agents/durable-execution.md))

### Observed Think mechanisms

- Think owns an opinionated top-level/sub-agent loop, session persistence, streaming, resumption, and client tools. Its Session model stores a tree of messages and context blocks, supports non-destructive compaction, and indexes search with FTS5. ([Think source](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/packages/think/src/think.ts), [Think docs](https://developers.cloudflare.com/agents/harnesses/think/))
- `runTurn()` exists in `0.16.0` but is explicitly experimental. Its wait/submit/stream variants converge on the same persisted submission and recovery-fiber paths; an idempotency key belongs to the submission contract. ([`runTurn()` documentation](https://developers.cloudflare.com/agents/harnesses/think/#runturn))
- Experimental Actions add a settled-result ledger, optional durable approval, opt-in authorization, and reply attachments. Cross-retry deduplication requires an explicit stable idempotency key. If an isolate dies during execution, the row can remain pending/unknown; explicit-key actions may be reclaimed after the timeout, while missing-key actions surface `ActionPendingError`. Authorization defaults to fully authorized until the application opts into a policy. This is bounded at-most-once behavior on the documented happy path, not exactly-once execution. ([Actions contract](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/docs/think/actions.md))
- Experimental Channels supply overridable per-surface defaults for instructions, tools, and turns. Tool policy can narrow, but `beforeTurn` wins; a turn with no channel receives no channel policy, and several out-of-turn delivery paths are not wired. ([Channels contract](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/docs/think/channels.md))
- The built-in workspace is a Durable Object SQLite virtual filesystem. Its model tools include read/write/edit/list/find/grep/delete and an optional `bash` backed by `just-bash`; network access is disabled by default and storage/execution caps apply. ([Think package README](https://github.com/cloudflare/agents/blob/f08ee06fd610756de0d8abf539dfe9b746bdd7c5/packages/think/README.md))

### Unknowns and falsifiers

No live Worker deployment, eviction/recovery run, geographic-placement test, cost measurement, or sustained-scale test was performed. Agents claims are falsified by state divergence under concurrent clients, lost or duplicated scheduled/fiber work after eviction, child work routed to the wrong facet, or a non-idempotent external effect repeated on recovery. Think claims are falsified by message loss/duplication on reconnect, an approval applied to the wrong action, an unexpected privilege on a channel-less turn, duplicate effects after pending-ledger reclaim, recovery exhaustion without a visible terminal state, or compaction/search returning a different message branch than requested.

Think, `runTurn`, Actions, and Channels remain experimental. The `agents@0.21.0` release's Kitesurf browser support is connection-scoped and explicitly lacks a durable session, live view, recording, pause/resume, and Kitesurf Quick Actions; do not broaden it beyond the [release contract](https://github.com/cloudflare/agents/releases/tag/agents%400.21.0).

### Observed mechanisms

- The concrete agent loop claims queued input, opens durable turn/step boundaries, assembles system prompt/tool schemas plus event-derived history, streams the provider, runs tool calls, and appends model-visible facts back to the session log before deriving the next request. The session is an append-only event log; message history is a projection, not a separately authoritative transcript. ([core subsystem](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/subsystems/core.md), [session source](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/index.ts))
- Parallel-safe tool bodies may overlap within a bounded rolling pool, while exclusive calls form barriers. Pre-execution policy, durable results, and deferred result context commit in model order. Cancellation stops replenishment, drains started calls, and records synthetic results for calls skipped before dispatch. ([tool scheduler](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/agent-loop/src/tool-calls.ts))
- Crash-tail repair distinguishes a call never recorded as started from a recorded call whose durable outcome is unknown. It closes missing tool/step/turn boundaries and tells the next request not to blindly retry a potentially effectful unknown outcome. It does not reconcile the external system. ([repair source](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/core/session/src/repair.ts))
- Cordis gives plugins dependency-scoped fibers. Services and event listeners register as effects owned by the active fiber; missing or replaced dependencies drive unload/reload. Within one `effect()`, collected disposers execute in reverse registration order and async cleanup is awaited. At fiber unload, top-level effect wrappers are cleared and awaited concurrently. Therefore “reverse order” applies inside an effect's disposer chain, not as a proven global ordering across every plugin effect. ([vendored fiber implementation](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/vendor/cordis/src/fiber.ts), [standalone implementation](https://github.com/cordiverse/cordis/blob/8cc9e33fab69e2d0476d126baaf2acb24e6a6ab4/packages/core/src/fiber.ts))

### Observed mechanisms

- The command plane separates a central authenticated fleet API from per-host daemons that own local processes, protocol adapters, PTYs, and filesystem authority. The central registry routes and projects host state; it is not itself the process authority. ([architecture](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/docs/architecture.md))
- The context plane stores normalized event/span facts in partitioned Parquet and builds DuckDB views over them. Mutable summaries, briefs, decisions, embeddings, queues, and current fleet state live separately and retain source/provenance links. Derived context is explicitly replaceable projection, not new raw truth. ([context-store contract](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/docs/context-store.md), [schema](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/src/drover/schema.py))
- Release polling publishes a target through the heartbeat path. Hosts install a checksum-verified wheel and hash-locked dependencies beside the active runtime, smoke-test it, then activate only when both structured sessions and PTY sessions are provably idle. Unknown quiescence is treated as busy. A marker records prior/target versions; failure to re-register after restart triggers rollback. This is quiescent host upgrade, not migration or rollback of agent side effects. ([release fetch/install](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/src/drover/server/updates.py), [activation/rollback](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/src/drover/server/harness/updater.py))
- Unreleased Phase 0 models a project goal separately from a non-completing invariant, requires a runnable exit-code check, persists per-iteration brief/claim/diff/usage/verification facts in a scratch ledger, and enforces iteration/token caps from that ledger. It stops a project only on the check, a cap, a permanent harness failure, or human interruption. ([goal contract](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/scripts/loop_engine/goals.py), [driver](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/scripts/loop_engine/driver.py), [ledger](https://github.com/arniesaha/drover/blob/e1b8e460830c4f46565c5f3ed5e1de75b23a9684/scripts/loop_engine/ledger.py))
